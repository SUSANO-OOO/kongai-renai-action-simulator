# 製品完成・公開の受け入れ条件

素材査定完了、コードのビルド成功、ゲームの完成、公開成功は別の段階。本人の承認を除きCodexは不足を見つけ、改善・再検査して進める。

## 製品として揃うこと
通常10面のNORMALとHARD、指定された秘密面、1体開始・3進路自由移動、青増員/赤減員、一時強化、敵/障害/射撃、コイン回収、スキン、経験値/称号、保存/復旧、設定/中断/再開、成功失敗の演出が、承認素材で一貫したゲームになること。解放順・秘密面モード・報酬・配布は未回答Qを勝手に確定しない。

## 証拠
- 基本ルール：0/1/99/100/大きな人数、ゲート二重発火防止、範囲外入力、終了後イベント、リトライ初期化、報酬二重付与を実装に対して検査。
- 各面：NORMAL10面/HARD10面の少なくとも1つの実操作で成立するクリアルート、代表的な失敗、解放条件を確認。机上探索やテスト用人数注入を本番の完走として数えない。
- プレイ品質：3弱点の製品段階チェック。複数の初見反応は実測と明記し、架空テスターを作らない。
- 表示と操作：9:16を含む複数縦長比率、安全領域、ブラウザバー、ポインタ取消、複数タッチ、中断/復帰、読み込み失敗、WebGL非対応/コンテキスト喪失を確認。
- 性能：対象実機、OS/ブラウザ、版、シーン、計測方法を残す。60fpsを狙いつつ持続不能な端末には品質調整。目標と実測を区別し、フレーム時間、メモリ、音切れ、発熱、長時間周回で判定する。PCのエミュレーションをiPhone実機と記載しない。
- 音：初回ジェスチャ解除、BGM/SE音量、ミュート保存、バックグラウンド復帰、同時音の破綻、白金/紫ゴールの同期を確認。
- 保存：不正/破損/旧版/容量制限、バージョン移行、報酬の一度だけの確定、明示操作なしに既存記録を破棄しないことを確認。
- 権利/プライバシー：素材とフォントの配布権、肖像、作者名義、公開コミット情報、機密ファイル不在。OSSライセンスや課金/解析を勝手に追加しない。

## 公開と引き継ぎ
配信はGitHub Pagesを候補とするが現時点で有効化済みとは扱わない。公開権限を確認したうえでタグ/版/SHA、ビルド、公開URL、初回ロードとキャッシュ更新、起動→1ラン→再挑戦のスモーク、戻す版と手順を記録する。公開後確認前にrelease完了としてIssueを閉じない。
`data/project-state.json` のreleaseChecksは証拠への索引。`npm run check:release` は前提の欠落を検出するもので、美術や面白さの自動合格器ではない。
