# 素材先行・査定の検収契約

## なにを承認するか
ゲームに使う完成素材を先に揃える。対象は人物、味方/敵/ボス、11環境、小物/障害/ゲート/ゴール、モーション、UI、VFX、BGM/SE、フォント/アイコン。`data/asset-requirements.json` は最低限の網羅範囲であり、最終ファイル数を固定するものではない。共通リグ/マテリアル/音の共有は、品質と個性を損なわなければよい。

## 状態と証拠
`data/asset-manifest.json` を唯一の素材状態台帳とする。`not_started → in_progress → preview_ready → qa_passed → awaiting_user_review → approved`。修正は `rework_required`。状態名だけを書き換えて実体を省略しない。

`preview_ready` 以降は各項目に `sourceFiles`、`runtimeFiles`、`previewFiles`（リポジトリ相対ファイルパス配列）を持たせる。`qa_passed` 以降は `qaEvidence` と `license: {status: cleared, reference: ...}`、`approved` はさらに `approvalEvidence` を持つ。条件付きで不要な形式は、代わりに理由と査定用の等価物を記録し、台帳項目を黙って削除しない。

全体の `approvedForProduction` をtrueにするには、全必須素材が承認済み、異なる観点で3周以上の `auditRounds` の記録、`producerReview` の本人承認記録が必要。`assetSetSha256` は対象ファイル群から `assetDigest()` で計算する。承認後に実体が変わったら同じ承認を流用できない。

本人承認の証拠文書には、本人の正確な回答、日時/参照元、対象素材と版、留保を記す。チャットの回答を代わりに記録できるが、回答を創作してはならない。検査プログラムは記録と整合性を確認するだけで、本人の意思や美術品質を認証するものではない。

## 素材の動作確認は先に行う
完成素材を検証するための3Dビューア、実ゲーム相当のカメラ/光、群れの負荷、タッチ入力、モーション・VFX再生、音の試聴は承認前に行う。キャンペーン/報酬/本編の完成を先行させる許可とは区別する。素材の完成に必要な単位/軸/原点/当たり判定/音量/画面比率を定め、あとで一括作り直しにならないようにする。

## 提出物
ユーザーが開いて見られる総覧、人物/背景/モデル/モーションのプレビュー、音の試聴、UI全画面、成功失敗の連続演出、ライセンスと技術チェックの結果、未解決項目を一括提出する。制作元は編集可能、配布用は実際に読み込めること。紙の仕様書やAI広告画像だけでの承認依頼は不可。

`npm run check:assets` は未制作時には失敗するのが正常。`npm test` は未制作状態の整合性を認め、正当な承認の追加を妨げない。
