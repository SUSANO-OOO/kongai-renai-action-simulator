# アセット先行制作・査定ゲート（最優先）

## なぜ最初に全素材を仕上げるか

従来の「仮モデルでゲームを完成→後から本モデル/UI/音声へ差替→全ステージ再テスト」という二重作業を避けるため。**仮データから実装を進める誘惑よりも、最初に美術・音響を確定させる。** ただしゲームの相互作用を妨げる無理なモデリングを防ぐため、仕様に基づく事前の衝突・カメラ・LOD寸法検査は行う。

## Phase A：絵柄・統一性の決定（全体承認前の方向確認）

- 作品ロゴ3案、配色/タイポ/照明のデザインシステム、成人女性10人の立ち絵10点、顔アップ・全身同一性の検査、パイセン素材参照の確認。
- 女性は同じ描画タッチ・陰影・筆致・人体比率、異なる顔型・髪型・服装・ポーズで識別。肌色の単純な差し替え不可。成熟した魅力と色気は表情、ポーズ、仕立て、光、佇まいで出す。全員成人（27〜36歳）。
- 人物画をそのまま背景に貼るだけで「キャラクター3Dモデル完成」とみなさない。

## Phase B：モデルとシーン素材を全件制作

- 編集元：Blender `.blend`、必要なマテリアル/テクスチャの作業元。納品：最適化済み `.glb`、LOD、モーション、透過ポートレートWebP、サムネイル、ライセンス/来歴。
- モデル検査：前/横/後/斜め、回転台、走行カメラ、被弾、消滅、集団重なり、両端レーン接触確認。各ステージ固有の回廊と障害物が揃うこと。
- 画面素材：ステージ選択、個別人物詳細、Normal/Hard、施錠状態、スキンショップ、ユーザーレベル/称号、タイトル、HUD、ポーズ、リザルト、敗北、隠し解放演出、設定、クレジット。390×844に加え360/430幅を必ずデザイン。
- 音：全操作/撃破/集団増加/減少/コイン/ボス/報酬のSE、メニュー/ステージ/隠しステージBGM。音素材はすべて原本とゲーム用ogg/モバイル再生確認付き。

## Phase C：3周検査（本人査定の前）

1. 造形レビュー：人の手による企画・表情・顔同一性・個性・ボスのシルエット・コース視認性・チープな既視感の排除。
2. 技術レビュー：GLBロード、アニメ、骨/テクスチャ/PBR/LOD、端末FPS、画面ごとのUI安全域、音量/クリップ/途切れ、素材の実ファイル存在と版管理。
3. 整合性レビュー：11面/10人＋パイセン、Normal/Hard、15称号、コイン/3スキン、100体ゴールを含む全仕様との対応関係。差し戻し案件は修正後に再検査。

## 承認条件

- `data/asset-manifest.json` の **required全件が作成済み**、編集元存在、レビュー画像/動画存在、使用権利が確認できる。『仕様書あり』『仮形状で代用』は不可。
- 全画面のサンプルUIを、実際のスマホ縦サイズでタップ領域/可読性/一貫性チェック。
- 10人の立ち絵を横一列・個別全身・ステージ選択カードで比較でき、同じ人物が2D/3Dで一致。
- プレイヤーの査定要求はチェックシートと視覚比較、短い動画、音声サンプルを添えて**一回で総覧できる**形で提出。査定では修正依頼を受け、承認が取れるまで実装フェーズを開始しない。
- 承認後に初めて素材版を固定し、プレイアブルの構築・チューニング・回帰テストへ移る。

## 厳密な状態ラベル

`not_created`（未制作） / `draft`（試作） / `review_ready`（審査用一式） / `changes_requested`（差戻し） / `approved`（承認済み） / `rejected`（不採用）。この初期パッケージの最終素材は未制作。決して完成と混同しない。

## 承認データの更新規則

`data/asset-manifest.json` の `producerReview` は本人の明示承認だけを記録する。作成/検査をしたCodexが自身の判断で `approvedForProduction=true` にしてはいけない。本人の承認を検証できる参照（Issueまたは会話中の具体的な確認）、対象素材リビジョン、承認日時を揃え、required全件が `approved` になった場合のみゲートを開く。未制作から制作中に進行しても自動テストが妨げないよう、テストは状態整合性を検査する。
