# 05 — UI・UX・アニメーション仕様

> **2026-11-01改訂優先ルール:** `AGENTS.md` と `docs/ART_FIRST_APPROVAL.md` が最優先です。現行コードは未査定の試作であり、全アート/UI/音響の制作・制作者査定が終わるまで本格実装に進めません。通常10面＋HARD10面＋隠し1面。詳細は `data/characters.json`, `data/progression.json`, `data/secret-stage.json` を参照。


## デザイン原則

「広告の操作は5秒で理解できる。しかし画面は安っぽくない」を狙う。原色を並べただけのUI、無意味な六角パネル、過剰なグローは避ける。背景の肉色に対してUIは暗色透過パネル＋白文字＋局所アクセントでまとめる。

### ベースレイアウト

- スマホ縦: 390×844 CSS pxを設計基準、360×740〜430×932を最低適応レンジ。safe-areaを上下左右に反映。
- 画面上: 左に `STAGE 03`、中央に細い進捗レール、右に設定/一時停止。
- 画面上から約20%: ユニット数（主指標）・ATKアイコン・現ラン強化をコンパクトに表示。
- 画面中心〜下2/3: 常時ゲーム空間を優先。操作スティックを常駐させない。
- 画面下: 初回のみ「左右にドラッグ」。通常時は操作妨害のない半透明薄HUD。
- ボス: 画面上中央に名前・HPバー。通常HUDの位置を邪魔しない。

## 画面一覧

| 画面 | 内容 | 必須挙動 |
|---|---|---|
| タイトル | 大きな作品ロゴ、3D精子リーダー、現在ステージ、START、スキン、設定 | STARTを押すまでゲーム進行しない |
| ステージセレクト | 10面の解放状態と特徴、星/ベスト記録 | 未解放は押せない、クリア面は再遊戯可 |
| プレイ中 | ステージ、進捗、軍団数、強化、PAUSE | 誤タップ防止、ゲーム情報が隠れない |
| ポーズ | 再開、最初から、タイトルへ、音量/低画質 | 停止中に進行・敵攻撃しない |
| 失敗 | 失敗理由、残り距離、再挑戦、選択へ | リトライは1タップ、操作復帰が早い |
| クリア | タイム、残存戦力、星、報酬、次へ | 次ステージ自動解放、進捗保存 |
| スキン工房 | 色・尾型・発光模様を3Dプレビューで比較 | 装備中の表示、選択保存 |
| 設定 | SFX/BGM、画質（自動/低/高）、振動、モーション軽減 | 設定変更が即時反映 |

## 入力詳細

- ゲーム領域: `touch-action: none`、Pointer Eventsで横ドラッグ。ゲームメニューは通常のタップ操作。
- どの高さから触れても動ける。ただしボタン上のタッチはゲーム入力と競合させない。
- ドラッグ開始時のXと軍団Xを記録し、相対スワイプ量で目標位置を更新。**指の絶対位置へ軍団が瞬間ワープしないこと。**
- 指を離しても同じX位置を保つ。ドラッグ中に端まで達しても滑らかに止まる。
- デスクトップはマウスドラッグ、キーボード左右はデバッグ補助として対応可。

## 操作レスポンス

- 横入力の遅延を最短化。目標Xへ指数補間（目標0.08〜0.15秒）を初期値とし、実機で触って調整。
- 軍団はリーダーよりわずかに遅れて追従、リーダー自体の操作は重くしない。
- 3レーンの境界線は淡い溝。スナップ不可。危険物は接触直前ではなく遠景から見える。
- 画面の縦スクロール、文字選択、ダブルタップによる誤ズームを抑止。

## 数字と情報

- `軍団 123,456`：文字サイズは本数に応じて自動縮小。数が大きい場合は `1.2億` のような略記。
- `×20` `+100` などは白文字と境界コントラスト、背景だけで認識できる配色を避ける。
- 大きすぎる整数に対して、表示専用の略記と正確な内部戦力値を分ける。
- 視覚に頼らず音や振動でも伝達するが、音を切ってもプレイ可能にする。

## ビジュアルレビュー基準

- 60〜100%縮小表示でもゲート倍率・危険・軍団数が読める。
- UIが画面の中央を覆って回避の邪魔をしない。
- iPhoneのDynamic Island/ホームインジケータ、Androidのナビバーと重ならない。
- 過度に露骨な性的表現や実写画像を使わず、架空のコミカルなゲーム世界として統一。
