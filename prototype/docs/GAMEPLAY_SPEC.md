# 02 — ゲームプレイ詳細仕様

> **2026-11-01改訂優先ルール:** `AGENTS.md` と `docs/ART_FIRST_APPROVAL.md` が最優先です。現行コードは未査定の試作であり、全アート/UI/音響の制作・制作者査定が終わるまで本格実装に進めません。通常10面＋HARD10面＋隠し1面。詳細は `data/characters.json`, `data/progression.json`, `data/secret-stage.json` を参照。


## 1. 画面とカメラ

- 縦向き固定（ベース仮想画角 390×844。360×780〜430×932で欠けない）。端末のsafe-areaへ適応。
- 背面上方からゴール方向を見下ろす3人称パースペクティブ。平面横スクロールや固定トップダウンではない。
- 画面下1/3に味方の先頭・隊列、中央〜上部にゲートと敵の予告が入る。視点移動とズームは速度に対し滑らかに補間。
- 先行するアイテムは画面表示から到達まで2.0秒前後の読み時間を与える（ステージ進行速度により調整）。

## 2. 移動

- 自動前進。プレイヤーの指を左右にドラッグすると、群れの中心が滑らかに横方向へ追従する。指を離すと現在位置を維持。
- 3レーン中心は `L = -3, C = 0, R = 3`（ゲーム内単位）。レーン分割は設計上の目安。入力は**連続座標**で処理し、常時スナップさせない。
- 移動目標を `clamp(pointerDx * sensitivity + dragStartX, -maxX, maxX)` とし、入力に遅延がありすぎないよう0.08〜0.15秒程度の補間から調整。
- タッチとマウスのPointer Eventsを統一。マルチタッチは最初の指だけ。ブラウザのスクロール、ダブルタップズームはゲーム領域で抑止。
- 操作が初回から分かるよう2秒間だけ左右ドラッグのモーションガイドを出す。

## 3. 味方精子

- 主役の旗印となる**リーダー精子1体**＋従属する味方群体。小隊は頭部・尾部・ウェーブアニメがある3Dメッシュ。
- 先頭ユニットが進路選択の判定中心。軍団は後方に扇形〜流体型フォーメーションを作り、壁際で自然に圧縮。
- 群れ全体の戦力値 `troopCount` と可視メッシュ数 `visualCount` を分離。最大数を数百として描画し、1万・100万でも無数のMeshを作らない。
- 高倍率ゲートで数が増える時、隊列が広がり、瞬間的なインスタンス生成演出と数値ポップアップで成果を見せる。
- **各ステージ・NORMAL/HARD/隠し面の開始人数は1体固定**。中間で0体になればゲームオーバー。ゴール時に1〜99体なら失敗、100体以上で成功。開始人数の永続ボーナス禁止。

## 4. ゲート

| 区分 | 例 | 効果と演出 |
|---|---|---|
| 増殖（青） | ×2 / ×3 / ×5 / ×10 / ×20 / ×30 | `troopCount` を乗算。高倍率は後段に強敵/狭窄が待つ設計にする |
| 増員（青緑） | +5 / +10 / +30 | 数を加算。序盤の最低保証として機能 |
| 減員（朱色） | −10 / ÷2 | 損失。見た目と色で予告、基本は回避可能 |
| 強化（金） | ATK +1 / 連射 +15% / 範囲 +20% | 進行中の一時アップグレード。少数精鋭ルートを作る |
| 防御（緑） | シールド 1 / 耐性 + | 障害衝突の損失を軽減 |
| 変異（紫） | 尻尾ブースト / 貫通 | 特色のあるビルド分岐。強すぎる場合は出現制限 |

- 数式ゲートを読める文字サイズで表示、実際に通過した時のみ発火。フレームごとの連続発火を禁止。
- 3レーン全面を塞ぐ不可避な損失ゲートは置かない。ただし予告済みイベントとして特別な強制ボス戦を置ける。
- 場面により横2列のゲート、レーンごとに3択、ゲート＋障害物など組み合わせ可能。
- ATK/連射/シールド等の強化は**ラン内限定**。他ステージへ持ち越さず、保存もしない。

## 5. 戦闘

- 攻撃は自動。敵が前方範囲に入ると味方の頭部から**アクロショット**という架空の光弾を射出。
- 攻撃判定は群れ単位でまとめ、可視の弾は代表的なものだけをInstancedMesh/プールで演出。1体1弾・1体1AIの直列処理を避ける。
- 初期ターゲット優先順位: ①進路前方の最接近脅威 ②進路を塞ぐ破壊可能壁 ③周辺の敵。
- 簡易式（初期案）: `dps = baseDps * pow(troopCount, 0.55) * attackMultiplier`。人数だけで攻撃力が指数的に暴走しないよう後から実測調整。
- 倒した瞬間のヒットストップは弱く、弾道/頭部反動/敵破散/カウント減少を小気味よく演出。連続発射で画面を白く潰さない。
- 接触・敵攻撃・環境ダメージで人数減少。衝突時は部隊の粒子が一定数散り、カウンターが動く。
- リーダーは1体が別操作されるのではなく、軍団が0になるまで群れの中心として残る。

## 7. 地形・障害物

- 有機壁: 1〜2レーン占有。膨張/収縮パターン。安全ルートを残す。
- 粘液塊: 一時的に隊列が遅くなり、射撃速度減少。射撃で壊せるタイプもある。
- 逆流波: 軍団中心を横へ押す。予告エフェクトあり。
- 狭窄リング: 孔の開いているレーンを見極める。
- 収縮膜: 周期に合わせて通る。強制停止はせず前方進行との整合を設計。
- 発光胞子: 漂う危険球体。弾ける前に撃つと安全。
- チューブ分岐: 複数ルートのうち1つに進む選択ゲート。

## 8. 成長と報酬

- ラン中パワーアップ: 攻撃力、連射、貫通、シールド、尾部推進。ステージ終了時にリセット。
- 永続の戦闘能力強化は禁止。ユーザーレベル/称号は外見とプロフィールのみ。コインは外見だけを変える初期3スキンの購入用。
- スキン: 基本形状は統一し、頭部形状/目の有無/模様/尾の蛍光エフェクト/装飾アクセントを組み替える。チープな着ぐるみ化を避ける。
- 星3評価: クリア、残存戦力、被弾回数/ゲート選択の達成を組み合わせる。最適解が毎回同じにならないようスコア式を調整。
- **全ステージ開始は1体固定**。メインステージのゴールには**100体以上の生存**が必要。Stage 10のエンディングは卵子への到達を**SF風の抽象演出**で示す。実際の妊娠成立や日本の出生数増加を断定しない。

## 9. 調整方針

- 1ラン: 試作上は約40〜70秒。競合の実測と完成アート導入後の操作テストで調整する。序盤短め、後半長め。`docs/FEEL_BENCHMARK.md`を参照。
- 数を増やすほど常に正解、にはしない。高倍率レーン後の範囲ダメージ/壁、強化レーンのボス有利などを配置。
- 攻撃や衝突で極端に数が0になる理不尽死は避ける。警告→接近→回避可能性を守る。
- ステージ難度は目標勝率だけでなく、回復可能性・判断の余裕・再挑戦時間で検証。
- 高倍率を何度もかけると論理人数が急増するため、表示は最大3桁+単位（例: 12.5K, 3.2M）とし、内部は安全上限の範囲で扱う。計算上限はデータで明示する。


## W1〜W3の必須設計

- **W1 単調さ**：全11面で新しいギミック/敵行動/見せ場を作り、HARDは数値の水増しのみで終わらせない。
- **W2 品質の統一**：全完成モデル・UI・音を先に総覧し、制作者査定が通るまで本体実装しない。
- **W3 達成感**：全モード1体開始、100体クリア、1,000/10,000体以上は演出・評価向上のみ。人数の増加を密度・音・動作で見せる。

詳細と合否の証拠は `docs/THREE_WEAKNESSES_PREVENTION.md`。
