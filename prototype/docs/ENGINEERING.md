# 06 — 技術設計 / データ / パフォーマンス / 品質

## 推奨スタック

- Web-first: Three.js + TypeScript + Vite。将来PWA対応、必要であればCapacitor等でネイティブ配布。
- 3Dシーンは描画層・ゲーム状態・衝突判定層に分離。UIはDOM/CSS主体。
- モデル: GLB/glTF。本体実装前に編集可能な3DソースとGLBを全素材分準備し、査定承認を受ける。既存の仮モデルは**旧試作表示専用**。承認前の新規ゲーム本体機能実装は禁止。
- コンテンツ: `data/stages.json` の10面を正本として読み、スキーマ検証する。
- 個人情報・トークン・APIキーをリポジトリに保存しない。公開リポジトリでも安全な状態を維持。

## 物理とコリジョン

- Xは連続範囲。レーン中心は `-3, 0, +3` の3点、通過判定は各ゲートのX幅で決定。
- 前進は自動。進行距離Zがイベント距離を横断するときのみゲートを一度だけ適用。
- 壁はX/Zの矩形または簡易形状、敵は前方スラブで射程・体当たりを扱う。3D物理エンジンへの依存は初期不要。
- 連続フレームで同じ障害/ゲートを二重適用しない。タイムステップをクランプ。
- 時間経過に伴うHPや戦力の損失は、フレームレートの違いで変化しない計算にする。

## 軍団の大規模計算

- **表示量と内部量を分離。** 内部人数は `bigint`（正確な有限巨大整数）。描画人数は端末ごとの上限値を越えない。
- **初期人数は各モード/各面1体固定**。`×30` を何度通過しても、精子のオブジェクトを戦力数と同数だけ作る実装は禁止。
- ショットも一体につき一発ではなく、「一部を代表描画」「戦闘は群れ全体で集約」を採用。
- 極大値でも数値表示・HP計算が破綻しないよう、UI用略記とログ圧縮の係数を使う。BigIntを不用意にNumberへ変換しない。
- 0に到達したら終了。ゴールでは100体以上なら勝利、1〜99体は失敗。有限の極大値を∞と誤表記しない。

## 効果とバランス

- 増殖: `troops *= BigInt(multiplier)`。強化: 攻撃力・連射・射程・シールドなどの別パラメータに加算/乗算。
- 基本戦闘は敵「軍団戦力」を持たせた集約モデル。被弾VFXだけ近距離の代表ユニットを表示。
- 一つのレーンを占有するゲートの幅と判定を一致させる。複数ゲートに同時当たりした場合は、最も重なりが大きい1つのみ発火する。
- 入力とゲート/敵・障害処理の順番を固定して、再現性のあるテストを書けるようにする。

## 端末性能目標

- 60 FPSを目標。低性能端末では30 FPSの安定を優先。端末・GPU・OSを検証ログに明記。
- 可視ユニット上限：低150 / 標準350 / 高650目安。テストで再調整。
- 長いコースを一度に描画せず、可視範囲だけ生成・プールする。GPUインスタンシングとLOD活用。
- 動的シャドー・透明エフェクト・多灯光源はモバイルGPUに重いので限定。
- `devicePixelRatio`を内部画質設定で制御（低0.85〜1.0、通常1.0〜1.5、高最大2.0程度）。
- 5〜10分連続プレイしてメモリ増加・描画破綻・音途切れを確認。

## セーブ・通信・公開

- ローカルセーブ: `kongai-action-save-v1`。完了面・各面ベスト・スキン・設定。
- 構造はversionでマイグレーション可能にする。ロード時の破損データは安全に初期化。
- オフライン動作はPWA化段階で対応。広告SDK・トラッキング・収益化は初期導入しない。
- ソース公開時のGitコミット名とメール、秘密鍵、開発用トークンに注意。

## 自動テスト優先順位

1. 10ステージデータに必須要素があり、イベントが進行順に並び、3レーン範囲に収まる。
2. 加算/乗算/損失/ダメージが `bigint` で正しく計算される。
3. ドラッグ入力とフリーレーンが正しく反応し、離してもXを保持する。
4. 各ゲートの二重発火が起きない。1レーン外と隣のゲートに誤接触しない。
5. 死亡時はゲーム進行停止、リトライで状態リセット。ポーズも状態停止。
6. iOS Safari/Android Chromeの縦画面でUIが切れない。
7. 10ステージ完走、失敗、再試行、スキン、再ロード、音量が通る。

## GitHub運用

- `main`を公開可能な安定ブランチとし、Codexは作業単位ごとに新規ブランチ/PRを利用する。
- 重大なゲームプレイ回帰を検出したらメインへのマージを止める。
- 規模を理由に検査省略しない。3ラウンド監査（機能・画面・性能）と修正を繰り返す。

## 3弱点の受入検査

`docs/THREE_WEAKNESSES_PREVENTION.md` と `docs/LEVEL_FLOW_ACCEPTANCE.md` を必読。`node scripts/route-preflight.mjs` は1体開始から100体を目指す**抽象的な経路テスト**にすぎず、完成ゲームの攻略可能性を証明するものではない。素材承認後に実機動画と当たり判定ログで補完する。
